public class Singleton {
    // 1. volatile ensures changes are visible to other threads and prevents reordering
    private static volatile Singleton instance;

    // 2. Private constructor
    private Singleton() {}

    // 3. Double-checked locking
    public static Singleton getInstance() {
        if (instance == null) { // First check (no lock)
            synchronized (Singleton.class) { // Lock only once
                if (instance == null) { // Second check (with lock)
                    instance = new Singleton();
                }
            }
        }
        return instance;
    }
}

Q5
t.run() is a standard method call: When you call t.run(), you are simply telling the JVM to execute the code inside the run() method right now, within the thread that is currently executing the caller's code. No new thread is created; 
no new stack is allocated. It is functionally identical to calling any other method in your code.

t.start() is a request to the JVM: When you call t.start(), you are asking the JVM to perform a set of behind-the-scenes tasks:
Create a new native thread in the underlying Operating System.
Allocate a new call stack for that thread.
Once the OS is ready, the JVM schedules this thread to run.
The JVM then calls the run() method on your behalf inside that new execution context.

Feature,t.start(),t.run()
Execution,Starts a new thread.,Executes in the current thread.
Concurrency,Achieves multi-threading.,No concurrency; purely sequential.
Invoker,JVM calls the run() method.,You call the run() method manually.
Lifecycle,Can be called only once; otherwise throws IllegalThreadStateException.,Can be called as many times as any other method.

public class DeadlockExample {
    private static final Object lockA = new Object();
    private static final Object lockB = new Object();

    public static void main(String[] args) {
        Thread t1 = new Thread(() -> {
            synchronized (lockA) {
                System.out.println("Thread 1 locked A");

                synchronized (lockB) {
                    System.out.println("Thread 1 locked B");
                }
            }
        });

        Thread t2 = new Thread(() -> {
            synchronized (lockB) {
                System.out.println("Thread 2 locked B");

                synchronized (lockA) {
                    System.out.println("Thread 2 locked A");
                }
            }
        });

        t1.start();
        t2.start();
    }
}

Deadlock happens because t1 holds lockA and waits for lockB, while t2 holds lockB and waits for lockA.
Fix: always lock in the same order

Thread t1 = new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) {
            System.out.println("Thread 1 done");
        }
    }
});

Thread t2 = new Thread(() -> {
    synchronized (lockA) {
        synchronized (lockB) {
            System.out.println("Thread 2 done");
        }
    }
});

Object Lock (Instance Lock): Associated with a specific instance of a class. 
Used by synchronized(this) or public synchronized void method(). 
Multiple instances of the same class can execute these methods simultaneously if they are operating on different objects.

public synchronized void method() {
    // object lock
}
synchronized (this) {
    // object lock
}


Class Lock: Associated with the Class object itself. 
Used by synchronized(MyClass.class) or public static synchronized void method(). 
Only one thread can execute a static synchronized method for that class across the entire JVM.
public static synchronized void method() {
    // class lock
}

synchronized (MyClass.class) {
    // class lock
}


Q11
The join() method allows one thread to wait for the completion of another. 
If thread A calls t.join(), thread A will pause and remain in the WAITING state until thread t finishes its execution.
Use case: When your main program needs the result of a background calculation before proceeding.

Thread t = new Thread(() -> {
    System.out.println("Task running");
});

t.start();
t.join();   // main thread waits here until t finishes

System.out.println("Task finished");


Q12
The yield() method is a hint to the thread scheduler that the current thread is willing to give up its current use of the processor.
Behavior: The thread transitions from RUNNABLE to RUNNABLE (it stays ready). 
The scheduler is free to ignore this hint. 
It is rarely used in production code and is mostly useful for debugging or very specific low-level scheduling scenarios.


Q13
A ThreadPool is a pool of pre-instantiated, reusable threads.
Instead of creating a new thread for every task, you submit tasks to the pool, and existing threads execute them.
It manages a TaskQueue (typically a BlockingQueue) that holds pending tasks waiting for an available thread.

Types of ThreadPools (via Executors factory):
newFixedThreadPool(n): Fixed number of threads.
newCachedThreadPool(): Creates new threads as needed, reuses idle ones (can grow unbounded).
newSingleThreadExecutor(): One thread only, tasks executed sequentially.
newScheduledThreadPool(n): For tasks that need to run periodically or after a delay.

Q20
1. synchronized
Simple built-in lock.

synchronized (this) {
    // critical section
}

Advantage: easy to use.

2. ReentrantLock
More flexible than synchronized.

Lock lock = new ReentrantLock();
lock.lock();
try {
    // critical section
} finally {
    lock.unlock();
}

Advantages:
can try lock
can interrupt waiting
can create fair lock
supports multiple conditions

3. ReadWriteLock
Allows multiple readers but only one writer.

ReadWriteLock rwLock = new ReentrantReadWriteLock();

rwLock.readLock().lock();
rwLock.readLock().unlock();

rwLock.writeLock().lock();
rwLock.writeLock().unlock();

Advantage: good for read-heavy scenarios.

4. StampedLock
More advanced read/write lock.

Advantage: Provides an "optimistic read" mode, which is even faster than ReadWriteLock because it doesn't always block. 
good for high-read scenarios.

5. Semaphore
Controls how many threads can access a resource.

Semaphore semaphore = new Semaphore(3);
semaphore.acquire();
semaphore.release();

Advantage: useful for limiting access, such as max 3 users at a time.

CompletableFuture
CompletableFuture is an enhanced Future. 
It supports async execution, callback, chaining, combining results, and exception handling.

CompletableFuture<Integer> cf = CompletableFuture.supplyAsync(() -> {
    return 100;
});

cf.thenApply(x -> x * 2)
  .thenAccept(System.out::println);

Main methods:
supplyAsync()      // run async task with return value
runAsync()         // run async task without return value
thenApply()        // transform result
thenAccept()       // consume result
thenRun()          // run next step without using result
thenCompose()      // chain another CompletableFuture
thenCombine()      // combine two CompletableFutures
exceptionally()    // handle exception
handle()           // handle success or failure
get()              // blocking get
join()             // blocking get, unchecked exception


Q23
Solution 1: Using synchronized, wait(), and notifyAll()
In this approach, the monitor object acts as the lock. 
Threads wait for their turn and signal the other thread once they finish their increment.

public class SynchronizedPrinter {
    public static void main(String[] args) {
        // The same instance is shared by both threads
        PrintRunnable runnable = new PrintRunnable();
        new Thread(runnable, "Thread-0").start();
        new Thread(runnable, "Thread-1").start();
    }

    static class PrintRunnable implements Runnable {
        private final Object monitor = new Object(); // Instance-based monitor
        private int value = 1; // Instance-based counter

        @Override
        public void run() {
            synchronized (monitor) {
                while (value <= 10) {
                    System.out.println(Thread.currentThread().getName() + ": " + value++);
                    monitor.notifyAll();
                    if (value <= 10) {
                        try {
                            monitor.wait();
                        } catch (InterruptedException e) {
                            Thread.currentThread().interrupt();
                        }
                    }
                }
            }
        }
    }
}

Solution 2: Using ReentrantLock and Condition
This approach is more flexible and mirrors the structure of your PrintRunnable class. 
We use a shared Lock and a Condition variable to coordinate the threads.

public class OddEventPrinterLock {
    private static int value = 1;
    // Must be static to be shared across all instances of PrintRunnable
    private static final Lock lock = new ReentrantLock();
    private static final Condition condition = lock.newCondition();

    public static void main(String[] args) {
        PrintRunnable runnable = new PrintRunnable();
        new Thread(runnable, "Thread-0").start();
        new Thread(runnable, "Thread-1").start();
    }

    static class PrintRunnable implements Runnable {
        @Override
        public void run() {
            lock.lock();
            try {
                while (value <= 10) {
                    System.out.println(Thread.currentThread().getName() + ": " + value++);
                    condition.signalAll();
                    if (value <= 10) {
                        try {
                            condition.await();
                        } catch (InterruptedException e) {
                            e.printStackTrace();
                        }
                    }
                }
            } finally {
                lock.unlock();
            }
        }
    }
}
